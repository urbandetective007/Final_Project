# עסקים מוכרים — `known_businesses`

## המטרה

שהרוטינה Game לא תדווח שוב על עסק שכבר נמצא. בריצה של 14-10-2026 שניים מתוך 8 העסקים שנמצאו כבר היו במערכת
(סי.בי.אל.אס עורכי דין, נרדה בן-צבי — שד בן מימון 8).

`known_businesses.xlsx` — כל העסקים שכבר ידועים:
- כל העסקים שבמערכת (טבלת `businesses` ב-Supabase) נכון ל-14-10-2026;
- כל העסקים מדוחות קודמים של הרוטינה (`excel outputs/` ובתיקייה הראשית — דוחות פגומים דולגו);
- 8 העסקים של הריצה מ-14-10-2026 (מתוך טיוטת המייל).

עמודות: שם העסק, כתובת, שכונה, סוג עסק, קישור, מקור (מאיפה הגיע), תאריך הוספה.

## איך הרוטינה משתמשת בזה

```bash
# לכל עסק מאומת, לפני שהוא נכנס לדוח:
python3 known_businesses/known_businesses.py check "<שם העסק>" "<כתובת>"
#   KNOWN → כבר קיים: לא נכנס לדוח ולא נספר ל-100   (exit 1)
#   NEW   → חדש: נכנס לדוח                          (exit 0)

# בדיקה אחרונה של הדוח כולו לפני השמירה — חייב להדפיס "סה"כ KNOWN: 0":
python3 known_businesses/known_businesses.py check-report "<דוח>.xlsx"

# בסוף הריצה — מוסיפים את העסקים החדשים לקובץ ודוחפים אותו יחד עם index:
python3 known_businesses/known_businesses.py add "<דוח>.xlsx" --source "רוטינה Game 14-10-2026"
```

## איך עובדת ההתאמה

עסק נחשב "כבר קיים" כשיש **אותה כתובת** (רחוב + מספר בית; "שדרות"/"שד'", "ירושלים", מיקוד ו-1/2 לא משנים) **וגם שם דומה** —
אחרי הורדת תארים (עו"ד, ד"ר, בע"מ, משרד...) וסימני פיסוק, בלי חשיבות לסדר המילים.
לכן "בן צבי נרדה" = "נרדה בן-צבי, עו"ד" באותה כתובת.

שם זהה בכתובת **אחרת** מודפס כ-`NEW (שם זהה בכתובת אחרת — לבדוק)`: הוא נכנס לדוח (אולי פועל גם בכתובת נוספת), והשורה עוזרת לבדוק ידנית.

## עדכון מהמערכת

עסקים שמעלים לאתר ממקור אחר (לא מהרוטינה) לא נכנסים לקובץ אוטומטית. כדי לרענן — לייצא שוב את טבלת `businesses`
ולהוסיף אותה (הסקריפט מדלג על מה שכבר קיים).
